# 独立运行目录与访问保护

通常使用[自行部署](自行部署.md)中的双击或命令行方式即可。以下是 Windows 上可选的高级部署工具，所有目录、域名和凭证均由部署者自行提供。

## 可选的独立运行目录

先按[异地联机](异地联机.md)配置自己的固定入口，再指定一个与源码分开的目录：

```powershell
npm run deploy:runtime -- -Root C:/Games/XiangWa -Port 4173
```

也可通过本机环境变量 `XIANGWA_RUNTIME_ROOT` 指定目录。没有指定目录时部署工具会报错，不会选择其他电脑的安装目录。

部署需要本机 Node.js、cloudflared 和部署者自己的入口配置。后续更新会保留目标目录的存档、访问记录及权限配置；更新前先停止该目录的运行实例。

部署后使用目标目录的“开始联机／结束联机／发放邀请码”。后台进程按记录的PID、启动时间、程序和命令路径核对，避免操作无关进程。可选的普通账户方案见[低权限运行](低权限运行.md)。

## 邀请码与资源上限

游戏默认使用限时邀请码保护新验证、新建与新加入。新码默认30分钟、5个浏览器，可以自行指定时长和名额。已经入席的玩家可凭原身份继续行动、刷新和重启恢复。

发码工具只在本机读取管理密钥，普通游戏页面没有发码权限。默认限制20间房、64条SSE连接、每名玩家4条SSE连接和128条HTTP连接，并有全局请求及验码额度。

程序化测试可不配置访问目录使用内存模式；日常运行入口默认开启访问保护。

## 数据与配置

存档、访问记录、隧道凭证、管理密钥、权限备份、日志及本机配置必须保留在部署者自己的目录，不提交 Git，也不打包给其他部署者。

更新前停止服务并备份自己的数据目录。新部署者应从空目录开始，不能复制其他玩家的身份凭证或进行中的秘密盘面。
