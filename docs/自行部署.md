# 在自己的电脑上部署箱娃

任何有仓库访问权限的人，都可以下载程序，在自己的 Windows、macOS 或 Linux 电脑上运行，由电脑或手机浏览器加入。这台电脑负责保存房间并提供游戏服务，开玩时要保持开机、联网和唤醒。GitHub 页面用于下载源码，下载后还需要启动本机程序。

## 下载与准备

1. 打开 [GitHub 仓库](https://github.com/Steven060206/xiangwa)，选择 **Code → Download ZIP**，完整解压到准备长期保留的文件夹。也可用 Git 克隆仓库。若仓库为私有，需要登录已获授权的 GitHub 账户；用 Git 克隆时也需要相应访问凭证。
2. Windows 一键版会自动准备 Node.js，无需手动安装。选择分步启动时，从 [Node.js 官网](https://nodejs.org/zh-cn/download) 安装 LTS 版本，要求 **Node.js 22 或更新版本**。安装后重新打开终端；Windows 安装程序应保留将 Node.js 加入 PATH 的默认选项。
3. 找到含 `package.json`、`server.mjs` 的项目根目录。游戏运行只使用 Node.js 标准库，**无需执行 `npm install` 或 `npm ci`**；这些依赖用于开发与浏览器测试。

新电脑默认使用本项目文件夹内的 `data` 保存自己的房间和邀请码。本机与局域网运行不需要域名或 Cloudflare 账户。

## Windows：双击使用

推荐从 [Releases](https://github.com/Steven060206/xiangwa/releases) 下载 Windows 一键版，完整解压后双击 **一键启动.cmd**。它会自动使用已安装的 Node.js 22+，没有时从 Node.js 官网下载便携版至当前用户的应用缓存，首次联机时复用或下载官方 cloudflared。无需管理员权限或手动安装 npm 依赖，源码 ZIP 也包含同一入口。

启动后自动发放30分钟、5个浏览器的邀请码，显示本机／局域网地址并建立临时公网网址。公网健康检查通过后自动打开浏览器，房主和朋友都从这个公网网址进入。保持窗口开启，输入 `I` 并回车发新码，输入 `Q` 并回车或按 `Ctrl+C` 停止本次服务和分享。临时分享失败时本机／局域网游戏仍可用。

仅本机／局域网试玩时运行 `一键启动.cmd -LocalOnly`；不希望自动打开浏览器时加 `-NoBrowser`。便携环境会缓存复用，房间与邀请码按下文配置保存在自己的数据目录，不会上传至 GitHub。

以下为保留的分步方式：

按以下顺序操作：

1. 双击项目根目录的 **启动游戏.cmd**。看到游戏地址后保持这个窗口开启。
2. 双击 **发放邀请码.cmd**，复制显示的邀请码。默认有效30分钟，最多供5个浏览器验证，包含你自己。同一浏览器的多个标签页共用许可。
3. 在主机浏览器打开 [http://localhost:4173](http://localhost:4173)，输入邀请码，填写昵称，选择四人／五人并创建房间。也可补齐人机，一个人试玩。
4. 同一局域网的朋友打开启动窗口显示的局域网地址，使用你发给他们的邀请码，再用房间码或房间邀请加入。
5. 异地联机时再双击 **远程联机.cmd**，按下面的“异地临时分享”使用临时 HTTPS 网址。

准备多人开局时，先选定大家共同使用的局域网或公网地址，房主也从这个地址创建房间。不同地址保存的浏览器身份不会自动互通。

如果启动窗口提示未找到 Node.js，先完成 Node.js 安装，再重新双击。调整配置后，按 `Ctrl+C` 停止旧游戏，再重新启动。结束联机时，先在远程联机窗口按 `Ctrl+C`，再在游戏窗口按 `Ctrl+C`。

## Windows、macOS、Linux：命令行使用

在项目根目录打开终端，先检查 Node.js 版本，再启动：

```sh
node --version
npm start
```

保持服务运行，在另一个终端进入同一目录，生成邀请码：

```sh
npm run invite
```

打开 [http://localhost:4173](http://localhost:4173)，验证邀请码并创建房间。朋友使用主机局域网地址或下文生成的公网地址进入，再验证、加入。

新邀请码默认30分钟、最多5个浏览器。自定义有效期和名额、查看或撤销邀请码可使用：

```sh
npm run invite -- --hours 1 --uses 5
npm run invite -- --list
npm run invite -- --revoke 邀请码记录ID
```

`--list` 返回每条记录的 `id`，撤销使用该 `id`。邀请码到期或撤销后会限制新验证、新建与新加入，已经入席的玩家仍可凭原身份继续行动和恢复席位。

## 局域网联机

- 手机、其他电脑与主机连接同一个 Wi-Fi／局域网，打开启动窗口显示的地址，例如 `http://192.168.1.10:4173`。
- `localhost` 只表示正在使用浏览器的那台设备。分享房间邀请前，房主也应先从局域网地址打开游戏，再复制邀请。
- 若本机能打开而手机打不开，检查是否处于访客 Wi-Fi、是否开启了设备隔离，或 Windows 防火墙是否拦截 Node.js。需要时仅允许 Node.js 通过可信的“专用网络”；程序不会自动修改防火墙。

## 异地临时分享

临时分享通过 Cloudflare Quick Tunnel 连接已启动的游戏，无需账号、域名或路由器端口转发。先保持 `npm start` 或“启动游戏”窗口运行。

### Windows

双击 **远程联机.cmd**，或在项目目录另开终端运行：

```sh
npm run share
```

若没有可用的 `cloudflared.exe`，首次会下载 [Cloudflare 官方发布的便携程序](https://github.com/cloudflare/cloudflared/releases)，后续复用。首次下载和每次建立隧道都需要联网。

### macOS／Linux

先按 [Cloudflare 官方安装说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/) 安装 `cloudflared`，确保终端能运行 `cloudflared --version`。macOS 已安装 Homebrew 时可运行 `brew install cloudflared`；Linux 按官方说明选择自己的发行版或下载对应架构的程序，并加入 PATH。

安装后，在项目目录另开终端运行：

```sh
npm run share
```

### 把网址发给朋友

终端显示类似 `https://example.trycloudflare.com` 的网址后，房主先从该网址打开游戏、验证邀请码并创建房间，再把网址、邀请码和房间邀请发给朋友。若已从本机地址入席，改用公网地址不会自动读取本机地址保存的身份，建议统一地址后再开局。

游戏和远程联机两个窗口都保持开启。临时地址的同步会自动使用轮询。停止分享时，在分享窗口按 `Ctrl+C`；游戏仍在主机保存进度。

重新启动临时分享可能得到不同网址，原浏览器身份不会自动转移。需要跨重启稳定使用同一网址时，可按 [Cloudflare 官方隧道指南](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/)配置自己的域名和命名隧道，例如 `game.example.com`，指向本机游戏端口。这是可选的后续部署方式；账户、域名和隧道凭证由部署者自行管理。

## 配置

默认无需创建配置文件。如需修改，把项目根目录的 `.env.example` 复制为 `.env`，用文本编辑器修改并保存，重新启动游戏及分享窗口。示例：

```dotenv
PORT=4173
HOST=0.0.0.0
DATA_DIR=data
COOKIE_SECURE=auto
```

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `4173` | 游戏监听端口；启动、发码和临时分享共同使用 |
| `HOST` | `0.0.0.0` | 允许其他设备连接；改为 `127.0.0.1` 时仅本机可连接 |
| `DATA_DIR` | `data` | 房间存档目录 |
| `ACCESS_DIR` | 跟随 `DATA_DIR` | 邀请码记录与管理密钥目录；需要分开保存时才填写 |
| `COOKIE_SECURE` | `auto` | 本机及私有局域网地址支持普通 HTTP；公网地址使用 Secure Cookie，须经 HTTPS 访问 |

相对目录始终相对项目根目录解析，也可填写绝对路径；Windows 路径可使用 `D:/箱娃数据`。系统或当前终端中已有的环境变量优先于 `.env`。`.env` 为本机配置，请自行保留；更新程序时继续使用同一数据目录。

例如将 `PORT` 改为 `4180` 后，`npm start`、`npm run invite`、`npm run share` 和三个 Windows 启动文件都使用4180。本机地址相应变为 `http://localhost:4180`。命令行临时覆盖发码或分享端口时使用：

```sh
npm run invite -- --port 4180
npm run share -- --port 4180
```

发码工具可用 `--directory` 指定其他邀请码目录，例如 `npm run invite -- --port 4180 --directory ./data`。覆盖时必须与正在运行的游戏一致。

`COOKIE_SECURE` 也可明确设为 `true` 或 `false`。使用自己的 HTTPS 反向代理时可设为 `true`；公网联机保留 `auto` 或设为 `true`。普通局域网 HTTP 使用默认 `auto` 即可。

## 存档备份与地址

- 游戏自动保存到 `DATA_DIR/rooms.json`；默认邀请码与管理密钥保存在同目录的 `access.json`。
- 备份、迁移或更新程序前，先按 `Ctrl+C` 停止游戏，再复制整个数据目录。如果单独设置了 `ACCESS_DIR`，也要复制它。每个数据目录只供一个游戏实例使用。
- `rooms.json` 含秘密盘面与玩家身份凭证，`access.json` 含管理密钥 `adminKey`。保管在主机，不要上传 GitHub 或发给玩家。更新源码时保留 `.env` 和原数据目录。
- 重启后用同一数据目录、同一浏览器和同一网址打开，可恢复原座位。不要清除浏览器站点数据。临时分享换网址、由 `localhost` 换成局域网 IP、换浏览器，都无法自动读取原地址保存的身份。
- 需要分享一份干净程序给别人时，从仓库下载或克隆，让对方首次启动时生成自己的数据；不要复制你的 `data`、邀请码管理密钥或隧道凭证。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 提示端口已占用 | 检查是否已启动一个游戏窗口；停止旧实例，或在 `.env` 修改 `PORT` |
| 发码失败或连接不到服务 | 先启动游戏；确认发码命令使用相同端口与 `ACCESS_DIR`，并在正确项目目录运行 |
| 邀请码提示过期／名额已满 | 在主机重新发码；已入席的玩家继续使用原身份 |
| 公网能打开页面但验证后仍要求邀请码 | 使用分享窗口输出的 HTTPS 地址；检查是否手动更改了 `COOKIE_SECURE` |
| `npm` 在 PowerShell 被脚本执行策略拦截 | Windows 使用三个 `.cmd` 文件，或在“命令提示符”运行命令；也可将命令中的 `npm` 写成 `npm.cmd` |
| 临时分享未生成网址 | 检查主机联网及 `cloudflared` 是否能运行；macOS／Linux 先完成安装，Windows 首次下载需允许访问官方发布页 |

## 开发与验证

开发或运行浏览器测试时，在项目根目录安装开发依赖后执行：

```sh
npm ci
npm test
npm run test:browser
```

浏览器测试优先使用 Windows 默认安装位置的 Chrome；未安装可运行 `npx playwright install chromium`。`npm run verify:references` 使用 Windows PowerShell 检查文档和参考照片。
