# 三个人机陪玩实施计划

用户目标：一名真人可与三个人机在现有网页中试玩，真人可选择箱娃或访问者。

## 功能边界

- 现有四真人房间与先准备、再开始、再抢箱娃的顺序继续适用。
- 房主在大厅点击“补齐人机”填满空位；人机自动准备，房主可在大厅移除人机。
- 抢选阶段等待真人抢选，或由房主点击“让人机当箱娃”；选定后直接进入道具阶段。
- 人机使用自己经过过滤的玩家视图选择动作，走相同规则校验、存档与广播流程。
- 基础陪玩策略覆盖开局、探索及必须回应的结算，不引入未经确认的规则或强制代替真人行动。
- 所有真人断线后停止人机推进，重连后恢复；重启恢复人机席位及对局状态。

## 实现顺序

1. `src/bots.mjs`：实现 `chooseBotAction(view, { random = Math.random } = {})`，返回动作或 `null`。仅接收自己的过滤视图。包括道具、地图、秘密开局、无声牌、探索、确认、回答、补位、继承、交换、灭火器、箱娃与箱人潜伏。抢选不自主抢，真人投降时才跟随。
2. `src/server.mjs`：增加人机创建与 `add_bots`、`bot_claim_hako`；`remove_player` 允许房主移除人机。`isBot` 标志进入公开席位，凭证不公开；每个房间最多一个延迟行动计时器，行动时重新读取当前房间并在副本上结算；仅有人类在线且存在人机动作时推进，关闭服务时清理计时器。
3. `src/storage.mjs`：兼容旧存档中缺省的 `isBot`，拒绝非法标记及人机房主。大厅最后一名真人离席时同时删除人机，防止遗留无人房间。
4. `public/app.js`、`public/index.html`：大厅填充、席位标记、移除及让人机抢箱娃，沿用现有按钮与手机布局。按钮按在线、权限、阶段和待处理操作锁定。
5. 主要开发完成后统一补测试：纯决策用过滤视图验证，HTTP覆盖权限、容量、自动推进、暂停、重连、存档恢复及失败不生效；浏览器覆盖真人两种阵营、实际点击、人机自动操作和隐私。
6. 运行 `npm test`、`npm run test:browser`、`npm run verify:references`、`git diff --check`；解决明确失败，更新说明与进度，统一提交Git；更新当前4174服务并保留存档。原隧道已停止，重建临时分享后实际验收新地址。

## 完成标准

- 一人建房即可补齐三个人机，真实界面可分别选两种阵营并进入探索。
- 人机自己的行动与必须回应的结算持续推进，轮到真人时等待。
- 访问者HTTP／SSE／轮询和DOM不出现箱娃秘密；机器人决策接口不接收其他人的秘密。
- 不修改尚未确认的卡牌效果；报告基础策略的实际能力边界。
