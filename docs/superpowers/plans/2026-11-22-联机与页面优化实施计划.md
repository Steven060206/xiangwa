# 《箱娃》联机与页面优化实施计划

2026-11-22 定稿，适用于四人和五人模式。检查基线为 `0.1.0-beta.4`（`afd804f`）。下列勾选框记录后续实施进度。

**目标**　让朋友顺利入席，让轮到的人知道该做什么、上一步是否成功、消息会发给谁，并让玩家在自然结局后带走一份公开复盘。

| 实施顺序 | 玩家可见的改动 |
| --- | --- |
| 第一批，优先解决会妨碍试玩的问题 | ① 入席重试认回原座位　② 弱网提交后恢复操作　③ 对讲机与同房消息分开　④ 手机地图点按 |
| 第二批，从邀请到每回合操作 | ⑤ 房间邀请说明　⑥ 大厅席位和主按钮　⑦ 同时准备的反馈　⑧ 翻牌与持牌　⑨ 键盘直达处理　⑩ 当前行动者暂离提示 |
| 第三批，换网址续局与终局复盘 | ⑪ 本人一次性座位恢复码　⑫ 保存公开复盘与长局回顾 |

**技术与规则依据**　沿用 Node.js 标准库服务、原生网页、SVG 地图、按座位过滤的 HTTP／SSE 视图和现有原子存档。界面使用项目的暖纸、墨色、朱砂主按钮和既有的桌面双栏、手机分区导航。座位恢复处理身份，游戏引擎继续决定行动是否合法。四／五人开局顺序、随机发技能、无声标志、打断、道具、胜负、撤销及结束流程均按当前版本验收。[设计规范](../../../DESIGN.md) · [当前玩法](../../../README.md) · [已确认的同步约定](../../流程优化与同步修复方案-2026-11-16.md)

**轮询决定**　维持现有同步频率与响应方式。本轮已划掉响应压缩和空闲时返回“无更新”两项工作。下文的“核对进度”是提交结果未知时的一次只读查询。

## 第一批　先解决会妨碍试玩的问题

### 1. 入席重试认回同一座位

- [ ] 玩家点击“加入房间”前，浏览器保存一条待确认记录，只含目标房间码、高随机性的私有申请凭据和到期时间。计划有效期为 30 分钟，单条序列化内容小于 1 KB。同一次申请点十次只更新这一条。正式座位身份写入后清理，过期记录在下次打开时清理；另开房间时按房间核对，旧响应只能清理自己的申请。浏览器限制本地存储时，本页仍可在内存中重试。
- [ ] 在原有加入请求上增加可选的申请凭据。服务端把摘要与新席位在同一次保存中写入。重复请求先找已经为这次申请分配的有效席位，再判断余位和开局状态。已成功入席的申请可以补领自己的身份，包括最后一席刚满、对局刚开始或邀请码刚到期的情况。真正的新入席仍需有效许可；旧客户端沿用原入口。
- [ ] 同名玩家各自入席。离席、移除或房间删除后，旧申请失效。凭据仅用于本人领回座位，房间快照、地址栏、日志和导出文件均排除该值。修改入口在 [入席页面](../../../public/app.js)、[房间服务](../../../src/server.mjs) 和 [存档](../../../src/storage.mjs)。

### 2. 弱网提交后恢复操作

- [ ] 普通对局操作发出时固定当时的房间、本人身份、动作参数及 `expectedVersion`。计划以 10 秒作为等待回执的上限。超时或成功响应遭截断时，显示“正在核对刚才的操作”，用原身份读取最新进度。核对请求也有超时，可在重连后继续。
- [ ] 例如玩家翻开第一枚牌后，服务端已进入其行动阶段，即使原回执迟到，只读核对确认当前状态后就恢复移动等合法操作。只收到聊天、在线状态或拼图预览时，继续核对。其他操作已经推进时显示真实的当前任务；单凭版本增长不能宣称刚才的操作成功。
- [ ] 结果未知期间只自动发读请求。若最新进度仍是提交前那一步，给“重新核对”入口；普通带版本的操作可由本人明确重试**刚才的同一选择**，沿用原参数和版本，以便服务器最多接受一次。明确拒绝按现有错误处理。撤销投票继续用原请求编号，离席继续核实座位是否已释放。旧回执不得覆盖新身份、新任务或下一次提交的状态。[提交与同步](../../../public/app.js) · [撤销控制](../../../public/undo.js)

### 3. 对讲机、同房和箱娃阵营各看各的对话

- [ ] 消息列表、发送范围、发送按钮指向同一会话。按钮按实际对象写“发给搭档”“发给同房玩家”或“发给箱娃阵营”，输入框附近保留接收者名称。界面根据服务端已下发给本人的消息，按频道和发送时的房间分组。
- [ ] 一个频道有未读时，点击消息提醒直接进入该频道；多个频道有未读时列出各自数量，由玩家选择。只清已读频道的角标。阅读或输入时收到别处的消息只加提醒。普通同步保留当前草稿；主动切换频道或实际接收范围变化时沿用现有草稿清理提示。
- [ ] 换房、对讲机失效或阵营变化后，本人曾收到的历史仍可按原频道阅读，发送只面向当前合法频道。保留 Enter 发送、Shift+Enter 换行和中文输入法确认。服务端继续按发送时的接收者投递。[消息界面](../../../public/chat.js) · [服务端频道](../../../src/chat.mjs) · [对讲机配对](../../../src/walkie.mjs)

### 4. 手机上的地图角落能点到

- [ ] 把收起状态的“角落位置对照”入口移到棋盘外的地图工具栏。窄屏放不下时让工具栏换行。展开后可滚动查编号，收起后将焦点还给入口。地图仍可平移、切楼层、定位自己及往返历史记录。
- [ ] 用真实坐标点按回归。375×667 竖屏把“10 · 餐厅 · 壁炉内”移入视口后，点其中心应选中 10 号，角落对照仍收起。再点入口查看和收起对照，确认棋盘边缘的其他角落也能选中。保留 01—24 固定编号及行李箱原有编号规则。[地图与角落对照](../../../public/app.js) · [手机布局](../../../public/layout.css)

## 第二批　从邀请到每回合操作

### 5. 朋友在验证邀请码前就能看见要去的房间

- [ ] “复制邀请”改为“复制房间链接”。需要入席许可时，复制成功后提示“房间链接已复制，请把有效邀请码另发给朋友”。保留局域网复制回退和已有同步参数。分享链接只包含进入房间所需的公开地址信息。
- [ ] 从含有效房间码的链接打开时，邀请码验证页即显示“即将加入房间 ××××××”。验证后保留房间码并转到加入表单。普通首页沿用通用入口；已有身份优先恢复，没有启用邀请码的部署直接入席。[入口结构](../../../public/index.html) · [许可与链接](../../../public/app.js)

### 6. 大厅显示座号，全员就绪后突出“开始游戏”

- [ ] 抢选结果产生前，席位显示座号、昵称、房主／人机标记及在线、准备状态。抢选成功后再显示实际角色。只调整席位文案，无须迁移旧房间中用于兼容的默认角色字段。
- [ ] 房主尚未准备时“准备”为主按钮。房主已准备且全员就绪时，“开始游戏”为朱砂主按钮，“取消准备”为次要操作。其他玩家看到自己的准备状态和等待房主的提示。成员变化后即时重算。全员准备、房主开始、再一起抢选的顺序照常执行。[大厅结构](../../../public/index.html) · [席位和按钮](../../../public/app.js)

### 7. 多人同时准备时，直接告诉每个人是否成功

- [ ] 保留服务端的过期版本拒绝。本人点击准备遇到明确的版本冲突时，读取最新大厅。如果自己仍未准备，在原按钮旁提示“你的准备还没生效，请再点一次”；如果自己的目标状态已经达成，直接显示该状态。取消准备对称处理。离开大厅或身份改变后清理旧提示。
- [ ] 五名玩家对同一版进度同时点击时，每一席的界面与服务端一致。被拒玩家可在原处再点，并最终使全员就绪。区分这次明确拒绝与第 2 项的回执未知，保留玩家本人下一次点击决定。[大厅提交](../../../public/app.js) · [现有版本校验](../../../src/server.mjs)

### 8. 六枚无声牌共用一个“持牌跳过”入口

- [ ] 常态下直接点一枚盖牌，仍一次翻开本人选择的那枚。点击唯一的“持牌跳过”只切换到选牌状态，提示“选一枚盖牌，持牌并跳过本回合”。此时点第几枚，就提交该枚的 `silent_skip`。提供“取消选牌”和 Esc，取消时回到直接翻牌。
- [ ] 合法性使用现有条件。数字 0 已翻开、连续翻牌已开始或鬼来电要求必须移动时，不能选择持牌。铃只影响合法的翻牌请求。沿用撤销与表单草稿的边界，普通同步保留仍有效的选择模式，换人、换阶段、撤销或选项失效时清理。盖牌数字继续由服务端保密。[无声卡面](../../../public/practice.js) · [铃和连续翻牌](../../../public/exploration.js) · [无声规则](../../../src/silent.mjs)

### 9. 键盘可从“座次”直接跳到本人要处理的控件

- [ ] 复用“前往处理”，使它在对局行动页也能用键盘聚焦。将其置于“座次”之后、楼层和地图热点之前。激活时展开当前任务需要的区域，直接聚焦第一个可操作控件，例如可翻的第一枚牌、收礼回应或撤销投票。
- [ ] 跳转只移动焦点。地图保留原有键盘操作，地图、我的、公开和消息页继续使用现有导航。等待或断线时只聚焦实际可读或可用的目标。用一楼七块地图的场景验收，从“座次”按一次 Tab 到入口，再按 Enter 到牌面；这两步产生零次游戏提交。[页面焦点顺序](../../../public/index.html) · [任务导航](../../../public/app.js)

### 10. 当前行动者暂离时，桌上其他人知道在等谁

- [ ] 把当前任务中**已经允许本人知道的行动者**与座次里的在线状态对应起来。例如“等待 2 号重新连接，回来后由他翻牌”。重连后恢复原任务提示。本人失联时继续优先显示自己的连接状态；已有另一标签页或轮询仍在线时，按房间现有状态显示。
- [ ] 只更新提示。匿名回应继续匿名，人机暂停沿用已有提示。暂离玩家保有原来的行动、回应和撤销投票权，全体真人离线五分钟的既定处理继续生效。[任务与座次](../../../public/app.js) · [房间在线状态](../../../src/server.mjs)

## 第三批　换网址续局与终局复盘

### 11. 换了联机网址，也能凭本人的一次性恢复码接回原座位

- [ ] 在“房间操作”提供“领取我的座位恢复码”。只有已入席真人能为本人签发，主动领取后显示并由本人保存。入口页提供“恢复原座位”，填写公共房间码和本人的恢复码。原网址优先走原有自动恢复。同一服务、同一房间数据换网址时，恢复已入席者也适用邀请码到期后续局的现有原则。
- [ ] 复用原身份校验和原子存档。可用 `POST /api/rooms/{code}/recovery-code` 签发，`POST /api/rooms/{code}/recover` 兑换。将恢复码摘要绑到本人席位，重新签发即作废前码。兑换成功即消耗；重复兑换不能交给第二个申请。原席退出、被移除或房间删除时一并失效。
- [ ] 目标浏览器在兑换前暂存私有申请凭据，用第 1 项相同的回执重试方式处理“兑换成功但回包丢失”。只有同一申请可以补领这次成功的结果。核对座号、角色、库存、房主身份和待回应流程都接续原席。签发、兑换均不推进游戏版本、不占新邀请码名额，也不新增可撤销步骤。恢复码和摘要不进入链接、公开／他人视图、聊天或复盘。
- [ ] 旧存档没有恢复码字段时按未签发处理，仍可从已登录的原浏览器领取。如果全体离线已经触发返回大厅，恢复后进入实际仍存在的大厅席位。玩家指引说明需在原席位可用时提前领取。[房间服务](../../../src/server.mjs) · [入口许可](../../../src/access.mjs) · [存档兼容](../../../src/storage.mjs) · [自行部署说明](../../自行部署.md)

### 12. 自然结局可保存公开复盘，长局可以回看关键回合

- [ ] 在四页终局复盘中提供“保存本局公开复盘”。默认导出可离线阅读的 UTF-8 文本，包含胜方与原因、总回合、分楼层终局盘面、按座号展示的最终物品与箱娃能力，以及开局、公开发现、死亡和结局。局中主动公开的发现按当时的角落记录；随身标志、自动公开手记及旧记录只使用当时已公开的信息。
- [ ] 将“按回合的关键记录”和“最近 64 条房间行动”分别标清。优先用现有初始发牌、带轮次的公开发现、死亡记录及正式结局组织关键记录，使早期里程碑能在长局看到。开局单列，事件沿用其实际无声轮次；旧档缺失的时间或位置不作推测。撤销后以恢复的盘面重新计算。
- [ ] 仅在收到正式终局后，从各席都可见的字段生成同一份报告，逐项选择导出内容。排除凭证、房间链接、聊天、对讲机展示、私有窥探记忆和撤销快照。只在玩家按“保存”时写下载文件；当前页可在内存保留最近一份已收到的公开报告。同桌退出使大家返回大厅后，留席玩家本页仍可点“保存刚结束的复盘”。本人退房、换席／换房、另开新局或撤销终局即清理；刷新后若服务器仍在终局，可重新生成。
- [ ] 正常结局后退出时明确提示“其他玩家也会返回大厅，退出前可先保存复盘”。中途结束、主动退出、全员离线结束仍走原流程；未产生正式结局就没有终局报告。[终局页面](../../../public/review.js) · [公开数据来源](../../../src/play.mjs) · [结束与离席确认](../../../public/undo.js)
