# 开局准备与基础回合接入

**状态：** 已实现并统一验证。62项模块与联机测试、1项四浏览器完整流程通过，桌面和手机截图已检查；资料验证覆盖39张照片。先完成主要开发，再集中测试，符合用户要求。

**目标：** 四人依序选取初始道具、完成地图、由箱娃秘密配置开局，然后体验无声翻牌、移动声明和确认、箱娃普通潜伏的完整循环。

**架构：** 沿用 Node HTTP/SSE 和原生网页。新增 preparation 纯规则模块；服务端保存开局秘密，通过逐玩家视图发送。现有 round 模块负责基础回合，网页继续复用地图。

**依据：** 新恢复的说明书第3—5页、已有卡面、[规则笔记](../../规则与首版范围.md)、[回合引擎](../../回合引擎.md)。

## 约束

- 保留访问者实际抽板摆板和双方门开口对接规则。
- 道具先选再拼图；全部地图完成后，访问者在正门等待箱娃配置。
- 密码为六枚中选择三枚，弱点从三种讨伐情况中选一；剩余标志才进入角落池。
- 保险箱固定写字台下，亡骸不能替换保险箱；原物移到唯一空角。
- 初始潜伏先选一间怨房查看，再在该房选角落，不能遍历两间怨房。
- 初始能力保留免手记门槛，不因此解除其他限制；无声模式移除NO.12。
- 页面明确当前回合仅支持无声翻牌、移动与潜伏；窥探、道具、能力结算、死亡与胜负继续开发，不展示为完整对局。
- 不把本局初始池数量当作整盒配件数量；依据完整准备步骤与已确认类别确定初始池。

## 实施单元

1. **参考资料与准备规则。** 原样归档16张说明书照片到 `references/rules/`，记录页码索引和开局规则；扩展 `tests/verify-project.ps1` 验证这些图片。
2. **开局引擎。** 新建 `src/preparation.mjs`：依序选道具、秘密选择密码与弱点、随机角落池、亡骸搬移、怨房查看与潜伏、初始能力。所有非法输入须在修改状态前拒绝，公开视图不得包含秘密。
3. **联机接入。** 更新 `src/server.mjs`：`start`进入`item_draft`，`choose_item`结束后进入原地图流程；`prepare_opening`进入`opening_setup`；逐阶段动作完成后创建基础回合。提供现有六类回合动作和按玩家过滤的HTTP/SSE快照。
4. **界面。** 更新 `public/`，增加道具选择、按角色显示的开局配置、六枚无声标志、移动目标、箱娃确认与潜伏。盖牌与箱娃位置不得进入访问者DOM。保留手机、桌面地图和刷新身份恢复。
5. **集中验收与交付。** 新增开局模块测试，扩充HTTP/SSE权限和保密测试，扩展四浏览器验收到一次完整回合循环；统一运行所有验证，查看桌面与手机截图，修复实际问题。更新README、AGENTS及规则状态，最后提交commit。

## 验收样例

- 非当前访问者不能抢选道具，已选道具不能重复选择；三人选完才开始抽板。
- 非箱娃不能提交密码，重复数字或越界数字不改变盘面。
- 初始随机角落池22枚、固定保险箱1枚、空角1个；亡骸放置后全部24角有物，原物无丢失。
- 访问者HTTP响应、SSE和DOM均没有密码、弱点、亡骸位置、潜伏位置、牌堆或未翻数字。
- 四人完成准备后从大厅开始；恰好10允许行动，超过10由未行动者在箱娃阶段后续轮。
- 移动先声明，等待箱娃确认后才改变位置；箱娃只能选择原房或相邻房的角落。
