# 《箱娃》流程优化与同步修复方案——完整修订版

本版完整替代上一版。目标是修复误操作风险、减少无意义确认、补齐游戏内指引，同时保持已确认的游戏规则、信息权限和胜负结算。

## 1. 已确认的问题与本轮边界

### 已复现的问题

| 问题 | 实际影响 | 优先级 |
|---|---|---|
| 开局密码勾选经过同步后显示错误 | 画面显示的选择与实际提交数字不一致 | P0 |
| 窥探“留在原处”经过聊天同步后恢复成“获取” | 玩家原先的决定被覆盖 | P0 |
| 赠送多选经过同步后额外勾选物品 | 只选夜视仪，却连同密码标志一起提交赠送 | P0 |
| 前端步骤标识未区分潜伏选房锁定、NO.4重排等阶段 | 操作定位、草稿保留和清理可能使用错误边界 | P1 |

前三项需要修复公共的表单状态处理，不能只针对单个按钮打补丁。保险箱猜数使用相同的重复控件标识方式，纳入同源修复与回归。

- 保留访问者声明后的箱娃确认／打断窗口，不根据隐藏能力决定是否自动放行。
- 保留准备后抢箱娃、依次选道具、实际拼图、房主开启配置、逐张翻牌等既定流程。
- 保留当前技术栈、游戏动作接口和存档格式。
- 已有32个文件的暂存修改与本轮修改作为一个完整版本，统一验证后创建一次 Git commit。

## 2. 具体修改

### A. 表单状态与同步一致性

**控件识别**

- 为开局密码、保险箱数字、赠送物品等重复控件提供稳定且唯一的标识。
- 表单恢复不能把重复的 `data-testid` 当作唯一定位依据。
- 不通过控件排列位置识别物品，避免库存顺序变化后恢复到错误对象。
- 同步恢复后统一计算勾选数量、说明文字、按钮状态和实际提交参数。

**草稿生命周期**

| 情况 | 处理方式 |
|---|---|
| 聊天、上下线、相同进度同步 | 保留当前有效选择、展开状态和阅读位置 |
| 合法选项发生变化 | 保留仍有效的部分；失效目标清空并提示重新选择，不自动换成另一个目标 |
| 当前操作成功完成 | 清理该操作草稿，按下一步骤重新初始化 |
| 请求明确失败且仍是原步骤 | 保留有效选择和错误提示，允许玩家检查后重试 |
| 撤销恢复、重开、切换房间或身份 | 清理相关旧草稿，依据最新快照重建 |
| 重连后进度已改变，无法确认仍是原操作 | 清理受影响草稿并要求重新选择 |
| 刷新页面 | 恢复服务器已提交进度；未提交草稿不新增持久化存储 |

步骤识别应覆盖结算种类及对象、潜伏房间锁定、NO.2路径、NO.4重排、本人角色变化和本轮阶段。不能仅凭房间、角色和大阶段判断“还是同一步”。

赠送草稿还需检查物品仍归本人、接收人仍合法、人偶转移限制仍满足。聊天草稿继续按现有频道逻辑独立处理。

**操作锁定**

- 提交中、断线及撤销投票期间，状态恢复不得重新启用游戏按钮。
- 在点击时确定本次动作参数及对应版本；重绘不能改变已经发出的请求内容。
- 同一次点击只提交一次，不因超时、响应截断或重连自动重发游戏动作。
- 明确拒绝与结果未知分别提示；结果未知时只读获取最新进度后再允许继续。

### B. 无声超限后的自动推进

只省略已经没有玩家决策的“结束反应窗口”。

| 超限后的状态 | 新行为 |
|---|---|
| 本次翻牌者存活且持有灭火器 | 保留本人使用／放弃窗口，禁止其他人推进 |
| 本次翻牌者没有使用资格 | 同一次服务端操作内进入箱娃准备阶段 |
| 合法持有者明确放弃 | 不消耗灭火器，随该次回应进入箱娃准备阶段 |
| 合法持有者使用 | 消耗灭火器，依原规则处理到期效果并跳过本次箱娃／箱人行动 |

必须保留：

- 恰好10仍可行动；超过10才走超限流程。
- NO.8与铃逐枚翻牌，超限立即停止，不跨周期补翻。
- 仅余最后一枚盖牌的触发路径保持原有行动先后。
- 到期NO.5在原阶段边界结算；群体死亡全部处理后，再处理合法继承。
- 灭火器使用者死亡时，续轮交给正确的存活访问者。
- 全员死亡或满足其他终局条件后停止推进。
- 哭喊、设置／回收、发动能力和潜伏仍由玩家决定。

自动推进只在相关成功动作中执行，不放入通用视图读取或任意后台循环。阶段初始化、总回合计数、NO.5结算和洗牌均只能执行一次。

### C. 窥探结算精简

| 窥探结果 | 操作方式 |
|---|---|
| 可获取标志 | “获取并按所选方式补位”或“留在原处，结束本次行动” |
| 不可获取标志 | 显示结果及原因，提供“结束本次窥探” |
| 手记 | 显示已自动公开，保留补位及夜视仪选择，再确认结算 |
| 保险箱 | 保留密码／听诊器选择及明确提交 |
| 当场死亡或获胜 | 进入对应结算，不再显示过期的窥探操作 |

具体要求：

- 取放决策通过明确按钮提交，不再用容易被重绘重置的局部布尔值承载。
- 保留所有合法补位方式，包括随身标志、空箱和符合条件的留空。
- 不自动消耗随身物品，不替玩家选择夜视仪奖励。
- 获取按钮明确展示将取得的物品和补位方式；关键目标失效时禁止提交。
- 保留主动公开发现入口，公开行为与取放行为分开。
- 关闭事件弹窗、查看历史或玩法说明均不提交结算。
- 继续调用现有 `resolve_peek`，不拆成多个网络请求。

### D. 保留必要步骤，改善操作衔接

- 潜伏继续先确认房间，再确认角落。选房前说明“确认后结束阶段能力选择”；选房成功后定位角落操作。
- 箱人仍等待箱娃完成阶段能力并开始潜伏，不能提前行动。
- NO.2路径、NO.4重排、重新盖放X和历史查看权限保持原规则。
- 遗物继承继续由死亡者选择接收人；不得因为库存为空或只剩一个接收人而擅自改变确认规则。
- 接收人死亡、物品被抢或其他待办变化后，页面依据服务端合法选项更新，不沿用旧选择。
- 当前任务、按钮、等待说明和事件导航使用相同的步骤判断，避免顶部提示与实际控件不一致。

### E. 简明玩法与线索摘要

**玩法说明入口**

在“房间操作”中增加“玩法说明”，使用独立原生对话框：

- 大厅、准备、探索和终局均可查看。
- 断线或撤销投票期间仍可阅读。
- 默认关闭，不自动弹出新手教程。
- 支持键盘、Esc、返回游戏及焦点恢复；关闭不执行游戏动作。
- 不与事件弹窗叠加。需要本人回应、死亡或终局等重要事件到来时，先关闭说明再显示事件；普通事件不打断阅读。
- 切换房间、重开或身份变化时清理旧的角色内容。

**说明内容**

- 两个阵营的目标与访问者三条胜利路线。
- 标准行动、自由行动、声明与打断。
- 无声阈值、持牌限制、连续翻牌及灭火器窗口。
- 箱娃准备、阶段能力、潜伏与箱人等待顺序。
- 死亡、继承、箱人及遗物戒指的胜利条件例外。
- 退出、结束、暂离及撤销的实际后果。

**修正文案**

- 密码标志代表保险箱未使用的数字，用于排除。
- 听诊器成功公开的是确认正确的密码数字。
- 讨伐情报代表对应武器无效。
- 手记展示的是能力说明，不代表能力已发动。
- 原图规则与本项目裁定按最新文档区分，不把历史版本写成当前规则。

**线索摘要**

放在“我的物品”中的折叠区域，标明“仅你可见”：

- 来源限定为当前过滤快照中的本人持有线索、公开发现和公开密码数字。
- 区分“当前持有”“曾被公开的发现”“已确认密码数字”，同一线索去重并保留来源说明。
- 不把历史公开发现当作物品当前位置。
- 不推断未公开库存、真实弱点、潜伏位置或某条胜利路线是否已经失效。
- 不增加永久私密笔记，不从聊天、日志或服务端完整盘面补取资料。
- 本人线索不放入“公开信息”区域，也不自动发布给其他玩家。

## 3. 事务、撤销、存档与兼容性

### 原子结算

一次玩家操作及其必然产生的自动推进共用一次事务：

1. 校验身份、版本、操作资格及参数。
2. 在副本中执行动作与必要结算。
3. 停在下一个真实决策点、待继承步骤或终局。
4. 保存成功后更新内存并广播。

保存失败时，盘面、库存、牌序、阶段、版本及撤销记录均不提交。不能先向客户端显示成功，再补存档。

### 撤销

- 自动推进归入触发它的动作，撤销恢复到整个动作之前。
- 保留原有本人直接撤销／共同投票分类，不因为合并步骤放宽权限。
- 撤销超限翻牌或灭火器回应时，一并恢复数字、阶段、到期效果、死亡状态、库存和继承队列。
- 撤销后的版本仍递增，人机继续遵守暂停机制。
- 撤销不回退聊天、身份和连接，不把恢复物品误报为新获得。
- 撤销说明继续隐藏技能名称、秘密目标和库存详情。

### 旧存档与旧客户端

- 不升级存档格式，不批量重写旧存档或撤销历史。
- 保留 `pass_noise_reaction`：旧存档若停在没有待回应者的反应阶段，仍可由原按钮继续。
- 已放弃的灭火器窗口不重新开放；旧NO.5窗口按现有兼容规则处理。
- 读取存档、GET、SSE、轮询和生成视图不执行新动作或死亡结算。
- 延迟到达的旧确认请求按版本／阶段拒绝，不能重复进入箱娃阶段。
- 新增玩法静态资源登记到现有白名单；不增加秘密数据接口。

### 通知与多人同步

- 同一最终快照可能同时包含超限、死亡和继承，通知必须指向最终有效步骤。
- 死亡、胜负和本人待回应优先，不能提示玩家进入已经被跳过的箱娃操作。
- HTTP与SSE重复到达不重复弹窗；首载、刷新和重连仍以当前状态建立基线。
- 保留NO.1—4静默、NO.5—10匿名宣告及NO.9回答的既有公开范围。
- 不通过新增等待提示、按钮或摘要暴露额外秘密。

## 4. 测试与验收矩阵

所有测试使用隔离服务和测试存档，不操作真实房间。

| 验证领域 | 必须覆盖的场景 |
|---|---|
| 表单一致性 | 开局密码、保险箱猜数、听诊器切换、赠送多选、补位、夜视仪、能力重排 |
| 同步触发 | 聊天、上线／离线、SSE、轮询、重复快照、延迟响应、本地导航重绘 |
| 操作变化 | 物品被抢、接收人死亡、目标失效、角色变化、潜伏锁定、重排开始／结束 |
| 无声阶段 | 恰好10、超过10、最后盖牌、持牌、NO.8、铃及二者组合 |
| 灭火器 | 本人／他人持有、使用／放弃、重复回应、离线后恢复 |
| 复杂结算 | 到期NO.5、群体死亡、使用者死亡、遗物队列、戒指例外、全员死亡、正确续轮 |
| 窥探 | 获取、留下、不可获取、空箱耗尽、随身补位、手记、夜视仪、保险箱、死亡与终局 |
| 原子性 | 保存失败、失败后重试、版本冲突、重复点击、两个标签页同时操作 |
| 撤销与恢复 | 自动推进整体撤销、投票期间导航、重启恢复、旧反应窗口、人机暂停 |
| 信息隔离 | HTTP／SSE／轮询数据及DOM均无新增秘密；公开区与私密摘要严格分离 |
| 玩法说明 | 键盘、关闭不执行动作、与重要事件协调、身份切换清理、离线可读 |
| 完整流程 | 四／五人、两种真人阵营、人机混合、开局至终局、重开与退出 |
| 布局 | 小屏竖屏、手机横屏、常见笔记本窗口；新增内容不遮挡操作或造成横向溢出 |

新增浏览器回归必须验证**实际发出的请求参数**，不能只检查勾选框或按钮是否存在。赠送测试要明确断言“没有多送任何物品”。

规则等价验收使用固定牌序和明确决策，检查决策边界的盘面、库存、牌序、能力、行动顺序、胜负一致。允许的差异仅为省略空确认、精简点击及对应事务／撤销步骤合并。

完整验证命令：

```text
npm test
npm run test:browser
npm run verify:references
git diff --check
```

保留现有规则断言；只调整确实由删除空确认导致变化的阶段预期。浏览器模拟、本机Chrome实测和手机真机结果分别记录。

- 玩家看到的选择与提交内容一致，普通同步不替玩家改变决定。

- 潜伏锁定、打断、继承及其他真实决策步骤完整保留。
- 自动推进可保存、可恢复、可撤销，不重复结算。
- 原有测试与新增回归通过，提交内容不含真实存档、凭证或本机运维资料。

本轮交付代码、测试、方案与说明、验证结果和提交号；正式服务部署与重启不包含在本轮。
